# 语音与 API 指南

[返回 README](../README.md) · [配置与维护](operations.md) · [配置模板](../config.example.py)

## 开启与操作

语音默认关闭。先按 [README](../README.md#快速开始) 安装可选依赖，再完成以下设置：

1. 「配置 → 语音模型」：开启语音，设置后端、API Key、模型、音色及必要的代理。
2. 「语音台 → 会话控制」：选择域与频道，手动进房／退房；域 ID、频道 ID 可一键复制。
3. 「房间成员」查看成员状态，「人格与记忆」管理提示词与共享记忆。

「设为默认」会写入 `OOPZ_CONFIG.default_area` / `default_channel`，供未指定目标的插件调用使用。
bot 只监听当前加入的频道；`listen_only_uids` 留空时接收房间主讲人的音频，填写后仅监听指定成员。

## 语音音量与临时闭麦

在「语音台 → 会话 → 麦克风与音量」拖动滑杆并保存，或在「配置 → 语音模型」调节「bot 语音音量（%）」，对应 `VOICE_AGENT_CONFIG.output_volume`。
默认 50%，即输出幅度降至原来的一半；旧配置未填写该字段时也使用 50%。
范围为 10%–100%，100% 为原始音量；保存后立即作用于正在播放和排队中的语音，
并在重启或重新进房后保留。该选项适用于 Live、MiMo 回复及进退房播报，调节时不会打断播报或重建模型会话。
音乐播放和远端成员的接听音量独立控制。

语音台的「关闭麦克风 / 打开麦克风」按钮控制 bot 发声。闭麦仍然接听，因此可以说“开麦”恢复。
闭麦为临时状态，不保存到配置；退房、重新进房或重启后恢复打开。**闭麦时调节音量会自动开麦**，包括已经达到 10% 或 100% 时再说“调小 / 调大”。

开启 `voice_volume_enabled`（默认开启）后，MiMo 和 Gemini Live 支持以下语义指令，模型会判断是否在指挥 bot，普通聊天中的转述不会按关键词直接执行。

| 示例 | 行为 |
| --- | --- |
| “调大音量 / 大声一点” | 增加 10 个百分点，最多 100%，自动开麦并保存 |
| “调小音量 / 小声一点” | 减少 10 个百分点，最低 10%，自动开麦并保存 |
| “音量设为百分之三十” | 设置为 30%，自动开麦并保存 |
| “闭麦 / 静音” | 临时停止 bot 发声，仍继续听取指令 |
| “开麦 / 恢复声音” | 恢复已保存的音量 |

语音控制不受普通回复概率限制；即使概率为 0%，仍可控制音量和退房。关闭语音调节开关后，WebUI 手动调节仍可使用。
进退房内部播报、手动提交给模型的文字回合及不明确的混合控制不会触发模型工具控制。

### 阿里 ASR/TTS 与 DeepSeek

安装更新后的 `requirements.txt` 和语音可选依赖。在项目根目录创建被 Git 忽略的
`.env.local`，写入以下两项；Linux/macOS 建议执行 `chmod 600 .env.local`。

```dotenv
DASHSCOPE_API_KEY=你的北京地域百炼密钥
DEEPSEEK_API_KEY=你的DeepSeek密钥
```

进程环境中的同名变量优先于文件。文件按数据解析，不执行 shell，不进行变量展开；
只有这两个模型密钥会自动加载。不要将密钥写进前端、示例配置或版本库。
修改密钥后重新保存语音配置或重启程序。控制台只管理模型、音色和接口地址，不返回这两个密钥。

在「配置 → 语音模型」选择「阿里语音 + DeepSeek（流式级联）」并开启语音，默认使用：

- ASR：`qwen-audio-3.1-asr-flash-message`，16 kHz 单声道 PCM；
- LLM：`deepseek-flash`，low 思考模式；
- TTS：`qwen-audio-3.1-tts-flash`，音色 `longanhuan_v3.1`，PCM 输出。

阿里接口可设置为对应业务空间的北京地域专属 WebSocket 地址；默认公共北京地址。
模型权限、地域与额度需与密钥匹配。先在「自检与试听」验证，再进入语音房。

输入由渠道按成员授权和 VAD 切句；达到最小音频窗口后，行为先扣一次尝试额度，
随即建立 ASR WebSocket 并持续发送本句增量（包括断句静音），不等待整句完成才上传。
启用 `intermediate_result_enabled=true`，临时转录按句 ID 覆盖；本地切句结束并收到
服务端最终转录后才交决策和记忆，临时转录不会触发回复、控制或持久写入。
仍保留本地 `silence_ms` 的停顿确认等待；本轮没有缩短它，也未向 WebUI 增加临时字幕。
在「配置 → 语音模型」的 DeepSeek 设置中选择「思考强度」：关闭（`none`）、
低（`low`，默认）、高（`high`）、最高（`max`）。点击保存并确认应用成功后，
从下一次生成回复生效，后续回复持续使用此档位；正在生成的任务保留原配置，无需退房或重启。
仅适用于 `aliyun_deepseek` 后端。对应 `aliyun_deepseek.reasoning_effort`，不支持自定义值；
更高强度通常增加等待时间，仍受表达任务期限和生成长度上限约束，不保证一定能产出完整回答。

DeepSeek 请求显式传递所选 `reasoning_effort`：`none` 时 `thinking={"type":"disabled"}`，
其他档位为 `thinking={"type":"enabled"}`。
只把正式回答 `content` 送入语音，`reasoning_content` 不进入 TTS、字幕、日志或权威历史；
正式回答出现思考标签或只返回推理而无正文时失败关闭，不猜测正文。
正常回复通过 DeepSeek SSE 按完整句送入双向流式 TTS，音频到达后即推送房间，
不等待整轮合成结束。控制意图先单独验证，控制 JSON 不进入 TTS。
若启用 AstrBot 记忆工具，涉及工具的 LLM 结果先完整处理，再流式输出 TTS 音频。
抢话达到配置门限后会取消当前生成并清空播放；退房、换房与停用会回收在途任务。
手动「直接朗读」、独立试听及进退房台词仍使用完整短音频返回。

识别流最多 64 帧、每帧 64 KiB、总音频 60 秒；应用最多 8 份识别租约。
采集断点、格式/采样变化、退房、切后端及超时关闭原流。被最新输入信箱替换的识别在
冷却加四秒后关闭，不写入上下文；已开始识别的失败/短句不退还尝试额度。
诊断 `asr` 包含与说话重叠的识别总时间，`asr_finalize` 表示输入结束后的收尾时间，
两者不是可相加的阶段，也都不是端到端首音延迟。

参考：[DeepSeek 思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)、[ASR WebSocket](https://help.aliyun.com/zh/model-studio/qwen-asr-message-websocket-api)、
[TTS WebSocket](https://help.aliyun.com/zh/model-studio/qwen-audio-tts-websocket-api)、
[DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)。

快捷开口需要已经进房：Gemini 显示「AI 语音回答」，将文字作为当前对话的一轮输入；MiMo 显示「直接朗读」，不经过语言模型。

Gemini 根据输入音频选择语言，人格后会追加中文普通话约束，但外语或音乐仍可能影响输出。
可进一步限定监听成员，或在人格中强调语言要求；`Live 回合：` 日志包含输入转写与回复，便于排查。

## 音频等待与阶段耗时

在「配置 → 高级选项 → 语音模型 → 音频等待」分别设置：

| 配置 | 默认 | 范围与含义 |
| --- | --- | --- |
| `first_audio_timeout_seconds` | 45秒 | 1到120秒；从开始消费生成流到首段音频，包含模型看图、思考、形成首句及TTS启动 |
| `audio_gap_timeout_seconds` | 10秒 | 1到60秒；输出首段后等待下一段音频的上限 |

设置适用于级联自动回复和快捷开口，保存从下一轮生效，不取消正在进行的回复。Live使用渠道默认预算。两项都不能延长原行动绝对截止：级联尝试从ASR准入起默认60秒，因此可等待时间还受ASR、决策和截图等已经消耗的时间限制。源帧等待、渠道传输（最多10秒）和播放排空（最多30秒）分别计时，失败停止/关闭源，不重播已发前缀。

`voice.generation.stage` 用原session/action/input/generation ID关联模型请求开始、HTTP响应头、正式首字、首个可合成句子、LLM完成、TTS启动/就绪/首音频/完成；`voice.playback.first_audio` 记录消费者等待首帧的真实时间。耗时均为单调时钟毫秒。模型阶段自请求开始累计，TTS阶段自TTS启动累计，流式阶段可能重叠，不能直接相加。图像理解与思考无法由当前供应商接口独立计时。日志和`voice_observation`只包含元数据，推理内容仍不会进TTS或历史。

超时原因区分 `first_audio_timeout`、`audio_gap_timeout`、`transport_timeout`、`drain_timeout` 和整轮 `deadline`，失败时已获得的阶段耗时仍保留。未记录到的阶段是未知，不能当作零耗时。

## 回复频率与强制关键词

当前 `aliyun_deepseek` 使用语义接话，替代随机概率和固定连续窗口：ASR 最终转写 → 准备当前上下文 → DeepSeek 输出严格 JSON `{"decision":"addressed|contribute|silent"}` → 行为模块授权 → 截图、正式回答与 TTS。`addressed` 表示叫名/对机器人追问，`contribute` 表示适合提供明确帮助，`silent` 表示继续倾听。所有成员遵循同一规则。判定器单独关闭思考、限时4秒；正式回答仍使用控制台配置的思考强度。判定结果和思维内容都不会送入 TTS 或助手历史。

转写命中强制关键词时优先回复，即使模型返回沉默、非法 JSON 或请求失败；其他输入遇到失败保持沉默，不退回随机抽样。模型可结合上下文判断“大飞鱼”等同音误识别，但不是可靠的语音唤醒词引擎。为接收短叫名，此后端采集/流式ASR门槛最多250毫秒，普通接话仍遵循配置的最短时长。没有收到音频、ASR漏字、冷却期间最新输入替换、播放时关闭抢话等仍可能造成漏回应；语义判断不能恢复未识别的呼叫。

诊断日志 `voice.reply.assessed` 只记录具名结果、原会话/输入ID及耗时，不记录正文。下面概率与连续窗口设置仅作用于 MiMo/Gemini/OpenAI 原路径，不控制 `aliyun_deepseek` 的语义接话。JSON协议依据 [DeepSeek JSON Output](https://api-docs.deepseek.com/zh-cn/guides/json_mode/)，非法、重复字段及截断响应均拒绝。


在「配置 → 语音模型」设置，保存后对后续回合生效：

| 字段 | 默认值 | 作用 |
| --- | --- | --- |
| `reply_probability_percent` | `30` | `0～100` 的回复概率；不是每十句固定回复三句 |
| `force_reply_keywords` | `[]` | 转写包含任一关键词时绕过概率限制 |
| `conversation_window_enabled` | `True` | 命中关键词后允许同一成员连续追问 |
| `conversation_window_seconds` | `30` | 追问窗口长度（1～300 秒），有效追问后续期 |

WebUI 的关键词用英文逗号分隔，例如 `Ooptra, 机器人, 小欧`。匹配忽略大小写、全半角、空格与标点，
`OOPTRA`、`Oop tra`、`Ｏｏｐｔｒａ` 均可匹配 `ooptra`；同音识别别名需自行加入列表。

`0%` 时命中关键词或处于连续对话窗口才自动接话，`100%` 时每次均允许回复；手动开口、进退房台词和语音退房控制不受限制。
关键词为空时不会开启连续窗口。MiMo 按成员隔离；Gemini 仅在能确认单一讲话成员时保留追问窗口，多人混合输入时清除，避免串给其他成员。换房、退房或 Live 重建会清除窗口。

### 自检与试听

「语音台 → 自检与试听」检查 Python、Playwright/Chromium、Oopz 连接、模型凭据、采样率与代理；可选网络检查不会进房，但会请求模型并可能计费。MiMo 网络检查验证对话模型，ASR/TTS 需实际语音或试听确认。
试听使用复制的配置和独立会话，只在当前浏览器播放 WAV，不修改当前房间、共享记忆或音色设置。文本最长 500 字，音频最长 20 秒；MiMo 进退房台词先 AI 改写再 TTS，Gemini 通过独立 Live 会话生成。
进退房试听可选择全局或某个域已保存的台词，也可随机抽取或输入临时文字。
旧配置缺少概率字段时采用 `30`，已有明确设置保留。

### 两种后端的差异

- **MiMo**：关闭语音退房控制且无关键词时，在 ASR 前决定是否跳过；否则先识别，再决定是否普通回复。
- **Gemini**：持续听取对话，按回复回合决定是否播放，因此降低频率不保证减少模型用量；跳过的回复不写入共享记忆。

Gemini 的输入转写与回复消息[不保证先后顺序](https://ai.google.dev/api/live)。
未播放的回复最多缓存 4 MiB，结束后保留 2 秒等待迟到转写，命中关键词后完整播放。
超时、超限或新一轮语音导致归属不明时，仅按概率处理，不把上一句关键词用于下一句。

## 语音控制退房

`voice_leave_enabled` 默认 `True`，旧配置缺项也开启；可在「配置 → 语音模型」关闭。
所有当前监听的成员均可发出请求，AI 判断是否为当前针对 bot 的退房意图，例如“退语音”“机器人，你先下吧”“你出去吧”“滚出去”；不是固定词匹配。
否定、引用、讨论指令或人类自己离开不应触发；实际识别效果取决于模型与 ASR，首次使用请在语音房验证。

识别后停止普通回复，随机使用所在域的自动串门 `leave_prompts` 并按人设改写，播放完离场语再退出。
空列表时使用默认“拜拜，我下了”；生成／播放失败或 20 秒超时后仍尝试退出。
成功后进入该域的**手动退房冷却**，不受普通回复概率限制。

退房期间暂停接听。WebUI／QQ 手动进退房会取消旧任务，避免旧任务退出新房间；
实际退房失败时保留房间状态与错误，并恢复接听以便重试。

| 后端 | 条件与影响 |
| --- | --- |
| MiMo | 先做 ASR；选中普通回复时可合并意图判断与聊天，未选中或短句仍独立判断退房。合并失败会回退退房判断并跳过普通回复；意图判断失败或超时不退房 |
| Gemini | 使用 [Live 工具调用](https://ai.google.dev/gemini-api/docs/live-api/tools)，模型或中转需支持；切换开关会重建当前模型会话 |

MiMo 的短语音控制入口最低为 250 毫秒（用户更低的设置保留）；未命中退房意图的短句仍受普通回复时长阈值约束，能量过滤仍生效。

## 抢话打断

`barge_in` 默认开启，`barge_in_hold_ms` 默认 300 毫秒。连续说话达到门限才打断 bot，人多时可适当调高。
Live 模式由客户端清空当前播放并丢弃本回合剩余音频，服务端使用 `NO_INTERRUPTION`，避免背景人声持续打断生成。
客户端不发送人为的“说完了”信号，避免缓冲音频碎片被误判为完整回合。

## 无人自动退房

无论通过 WebUI、QQ 插件还是自动串门进房，确认房间只剩 bot 自己持续 **30 秒**后，会复查成员并静默退出，不播放离场语。
有人回来、成员查询失败或无法确认 bot 自己的身份与房间时，重置计时；其他 bot 也算成员，不会被忽略。
进退房和换房会清除旧计时，避免旧房间的检查退出新房间。

此规则固定生效，不依赖自动串门的域开关、暂停状态或每日额度。
自动加入的房间退出后进入全实例自动冷却；手动加入的房间退出后进入该域手动冷却。
无人退房失败会保留实际房间状态与错误，两类房间都会在再次确认独处 30 秒后重试。

## 自检与决策记录

「语音台 → 自检与试听」支持环境检查、模型网络检查和独立短音频诊断。可上传最长 10 秒、最大 2 MiB 的 PCM WAV（8～96 kHz，单声道或双声道，8／16／32 位），分别查看转写、退房意图和语音输出结果。使用当前模型配置，可能产生模型用量，但不加入房间、执行退房或写共享记忆。

MiMo 可独立验证三个阶段；Gemini Live 没有独立意图返回，只有实际产生退房工具调用时才显示验证成功，普通短句未触发时显示跳过。浏览器试听也独立生成并只在浏览器播放，可随时停止。

会话控制展示最近 40 条回复／跳过决策及耗时，用于解释概率、关键词、连续窗口、短句和错误等情况；不保存原始转写或音频，重建后端会清空。MiMo 合并意图与聊天共享一次调用耗时，Live 阶段可能重叠，表中标注对应模式，不能直接把各列相加当作总延迟。

## 自动串门

需要可用的语音后端及语音总开关。在「语音台 → 自动串门」逐域开启；所有域默认关闭，旧 `auto_join` 已移除，残留字段忽略。

| 规则 | 默认行为 |
| --- | --- |
| 检查 | 全实例每 10～20 分钟随机检查一次，不会有人就立即进房 |
| 随机选择 | 符合条件且有真人的域等概率被选中，再随机选域内房间，按该域概率决定是否加入；默认 20% |
| 停留 | 10～20 分钟；到期最多等当前 bot 回复 30 秒，再进行告别，告别生成与播放最多 20 秒 |
| 自动退房冷却 | 全实例 30～60 分钟；仍允许手动进房 |
| 手动退房冷却 | 刚退出的域 2～4 小时，其他开启域仍可自动加入 |
| 每日上限 | 北京时间自然日全实例 3 次成功自动进房；可另设域上限；`0` 为不限；手动进房及已确认失败不计数 |
| 空房 | 房间只剩 bot 自己，持续确认 30 秒后复查并静默退出；查询失败视为未知 |

检查间隔与总上限为实例级设置，其他策略可按域覆盖，取消覆盖恢复继承。

### 进退房台词

每行填写一条表达意图，支持多条随机选择，每次由当前 AI 按人设改写：

- MiMo 使用文字生成与 TTS。
- Gemini 使用当前 Live 会话生成语音，无需额外 MiMo 密钥。

自动串门的空台词列表表示静默；**语音指令退房**的空列表则使用默认告别。
合成失败仍按停留／退出规则继续，台词不作为用户记忆，也不携带其他房间的聊天历史。

### 暂停、关闭与手动接管

暂停只阻止新的自动加入，当前自动停留仍按规则结束；恢复保留次数和冷却。
关闭域开关会告别退出该域的自动房间。手动房间不受自动停留时限或域开关影响，也不会自动换房，但同样遵循[无人退房规则](#无人自动退房)。
退出失败保留实际房间状态，并暂停后续自动加入。

### 状态异常与恢复

状态损坏、磁盘写入失败或中断进房留下未确认记录时，自动加入暂停；文字桥接与手动操作仍可使用。

1. 检查控制台与日志，核对账号实际所在房间并手动退出。
2. 停止程序，备份 `data/voice_auto_visit.json`。
3. 有未确认记录时，保守核对并补记当天成功次数及对应域次数，保持 `confirmed` 与计数一致，再清理对应 `pending`。
4. 修复文件后重启或点击恢复；未核清的记录继续保持暂停。

不要删除状态文件绕过当日额度。首次联调应分别验证 MiMo／Gemini 的进房问候、告别尾音、手动接管、空房退出及重启后的额度。
设计与验收记录见[需求说明](superpowers/specs/2026-10-06-voice-auto-visit-design.md)、
[实施计划](superpowers/plans/2026-10-06-voice-auto-visit-brand-release.md)和[更新日志](../CHANGELOG.md)。

## HTTP API 与插件

优先使用 WebUI 端口（默认 `3090`），鉴权令牌为 `WEBUI_CONFIG.token`。
以下路径均有等价的 `/api` 前缀别名，例如 `/api/voice/status`。

```http
GET  /health
GET  /voice/status
GET  /voice/members?area=&channel=
GET  /voice/channels?area=
POST /voice/join              {"area":"","channel":""}
POST /voice/leave
POST /voice/stop
POST /voice/speak             {"text":"..."}
POST /voice/diagnostics       {"network":false,"audio_wav_base64":"可选"}
GET  /voice/auto-visit
POST /voice/auto-visit/config  {"updates":{...}}
POST /voice/auto-visit/pause
POST /voice/auto-visit/resume
GET  /oopz/areas
GET  /oopz/channels?area=
GET  /persona
PUT  /persona
GET  /memory
POST /memory
DELETE /memory
```

`VOICE_API_CONFIG` 提供同路由、同响应的独立端口，默认 `3091`、关闭；开启后仍使用 `WEBUI_CONFIG.token`。共享密码为空时拒绝访问。

例如 [astrbot_plugin_ooptra](https://github.com/Eason4869/astrbot_plugin_ooptra) 默认接入 WebUI 端口，令牌填写 `WEBUI_CONFIG.token`；
独立端口也填写同一个 Token；旧 `VOICE_API_CONFIG.token` 与 `VOICE_API_TOKEN` 不再读取。绑定所需域与频道 ID 在「会话控制」复制。

## 回复前读取共享屏幕

`aliyun_deepseek` 使用 `deepseek-flash` 时，每次决定回复后会按需取当前频道单一分享者的最新画面，并与该轮问题一起发给模型；保留现有思考强度和只朗读正式回答的约束。不会持续上传视频或把图片保存到聊天记忆。画面可能包含题目之外的共享窗口内容；目前没有裁剪选区。

Oopz 共享屏幕使用独立的观看连接，音频连接本身不提供共享画面。渠道按当前频道成员的分享状态申请 RECEIVE 签名，以 audience 身份观看，不发布摄像头或麦克风。无分享、多人同时分享、超时及切房时不用旧图，继续文字回复。首次观看可能增加最多五秒等待；图片最长边 1920、JPEG 至多 1 MiB。仅支持当前已验证的 Agora 共享路径，其他平台实现或不可用签名不冒充成功。

已认证的 `GET /voice/screen`（或 `/api/voice/screen`）可按需验证状态；成功返回发布者、尺寸和 `jpeg_base64`，失败返回明确状态，不应将图片或签名写进日志。退房会关闭独立观看连接。

供应商依据：[DeepSeek 图像理解](https://api-docs.deepseek.com/zh-cn/guides/vision/)。
