# 应用装配与流程

本目录是五模块的装配、请求适配及跨模块流程，属于支撑层。业务实现、权威状态及静态依赖见 [系统架构](../../ARCHITECTURE.md)。原 `src/voice_agent/` 已删除，不保留重导出入口。

音频采集/成员标识绑定、VAD和输入队列归渠道；配额、概率、窗口、冷却、抢话许可和公告候选归行为；版本化情境/历史/outbox及授权归上下文；供应商协议、输出帧投影及任务终态归生成。系统配置、归档、更新和监督归维护。HTTP不直接写这些模块的内部状态。

试听没有单独的应用转发服务：WebUI直接装配 `dialogue.create_preview_service`。公告预设的查询/选择通过行为公开函数提供；配置默认目标由装配注入，协调器不自行读取配置文件。

## 流程所有权与完成语义

协调器保存应用任务、原渠道SessionRef、因果标识、请求代次和只读结果，不保存第二份可修改的当前房间。`channels.snapshot()`是实际会话权威来源。`turns`、`last_reply`、`speaking`和FlowObservations是界面/请求状态投影，不决定行为额度、历史事实或扬声器完成。

级联路径先取得行为尝试许可，再识别/解释控制，把事实交行为选择。语义判定需要上下文时先准备，只有Speak才启动表达；分类失败不能变成NoControl继续发声。整条流程最终结束原attempt，执行前失败反馈NotExecuted，执行后使用渠道实际结果，不重复扣额或伪造完成。

生成的单消费输出整体交渠道，应用不解析供应商分片或实现逐帧播放器。生成终态、播放排空、事务历史提交、外部记忆回执分别表达。只在实际播放完成及生成证据完整时记录完整助手回复，并绑定原会话与来源；切房之后已经确认的旧输出仍进入原作用范围，不能转到新房间。部分或不确定输出保留相应事实。SQLite提交交给流程拥有的线程任务，取消等待也观察到提交终结后才允许关闭上下文。

Live保持一个持续模型会话，应用只消费一次控制事件流，将提议交行为后传递Allow/Hold/Reject。输出任务与模型reader分离，慢播放不能堵住转录、工具取消或中断。输出与控制任务合计最多八个，显式请求最多八个，轮次及命令缓存各保留最多128项；停止/切房回收并等待，已经开始的提交不会成为孤儿线程；旧任务的finally不能关闭新流程资源。工具候选先由行为授权，再claim并执行渠道命令；已受理副作用继续观察真实结果，不能因HTTP或模型等待者取消而声称已撤销。

`ContextToolPort`绑定每次PreparedContext。模型只提供内容参数，生成适配将其转换为带原来源与已有grant的请求；上下文拥有者再次验证。来源变化重建流程，不把迟到工具结果送到新连接。

## 管理面

`RuntimeManagement`先阻止新业务请求，再停止调度和业务资源，报告未关闭清单。成功静默后维护持久化handoff，主循环才接受退出；父进程确认真实退出后执行部署切换。部分失败保留blocked状态，不执行切换。

候选部署在父进程提交之前只开放查询/health，配置、维护及业务副作用入口保持受限。bootstrap就绪、外部连接降级和业务激活许可分别观察；WebUI响应不代表Oopz已连接。正常退出先关闭控制台新请求并收完已提交保存/热应用，再停止语音和渠道资源。

这些模块已从原协调器抽出实际业务状态和执行，不以文件移动或类改名证明架构完成。保持公开契约时，供应商变化主要落在生成、策略变化主要落在行为、协议变化主要落在渠道，应用只负责传递和收尾；跨模块共同契约改变时才修改对应流程。

## 流式识别输入的拥有者

[recognition.py](recognition.py) 关联渠道增量、行为许可和生成识别流，不解析供应商协议。
达到最小音频窗口先准入一次，再上传；切句后以稳定 input_ref 交给原最新输入调度器。
被选中的流传入 `run_cascade`，复用原许可和最终识别，不再次扣额或重复上传。
最多8份租约；未选中的输入有冷却加4秒期限，原会话断点/退房关闭全部租约；
流式输入不绕过回复冷却、概率、关键词或上下文写入规则。输入在发言结束前开始识别，
因而后续识别失败或切句被判无效也消耗本次尝试。

支持图像的级联回复在行为允许发言、准备上下文之后，调用渠道 `capture_screen`，复查当前会话再传给生成任务；沉默和控制意图不取图。装配不理解观看签名或图片编码，捕获失败按文字路径继续。

语义级联在识别与控制解释后先将控制候选及原尝试许可交行为授权；可执行控制直接返回，不依赖 `assess_reply`。仅无控制或控制已禁用时才准备不可变上下文并判断普通接话，复查原会话后交行为决定；生成复用该准备结果。应用不解析模型JSON、不判断控制开关或决定是否接话。采集与流式识别使用同一最短输入门槛，支持250毫秒短叫名。

逐句诊断由 `FlowObservations.trace` 将原SessionRef/input/user、识别、行为原因及实际终态提交上下文的专用端口；有界40条耗时投影继续不含正文。流式识别租约拥有一个只观察最终结果的任务，使未被信箱选中仍已识别的句子可排障；关闭/失效同时收尾观察任务，不为诊断重跑ASR或授权发言。应用只调用非阻塞受理端口，队列、写入任务与关闭排空归上下文拥有；诊断写入失败只记录安全关联日志，不改变业务结果。Live未获得行动许可的轮次以明确的turn_finished证据结束诊断，标记not_executed；已有行动的播放终态仍由渠道回执决定；播放已完成后，历史提交等待被取消不能将诊断降为播放中断。
