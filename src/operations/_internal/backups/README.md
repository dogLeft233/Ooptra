# 备份与数据边界

`storage.py` 集中拥有归档范围、路径校验、内容摘要、SQLite 副本和恢复；`cleanup.py` 拥有有界盘点及清理对象指纹。公开入口见 [系统维护](../../README.md)。归档继续使用兼容 format=1，不暴露配置正文与密钥。

## 备份与恢复

`create` 在私有临时路径完成归档、CRC 检查及落盘后，原子发布最终 ZIP；查询和下载不会看到半归档。归档受管配置与 data 用户文件，排除维护记录、日志与缓存；检测 SQLite 文件头并通过 SQLite backup 取得包含 WAL 已提交记录的一致副本，不能只复制主文件。多个数据库及普通文件不是全局同一时刻快照；维护监督器在旧进程退出后再次建立最终快照。

`inspect` 验证归档并返回 `ValidatedRestore`，保留备份 ID 与完整归档摘要。`restore` 只接收该引用及监督器确认的 `StoppedDeployment`；恢复前和展开后均复查摘要，拒绝验证后被替换的归档。路径越界、链接、重复项、超额、摘要或清单不匹配均在覆盖真实文件前拒绝。替换失败按已知范围回滚，不自行拉起业务进程。

上下文 SQLite schema=1 由文件内容识别，不依赖固定文件名；备份和恢复拒绝高于当前支持版本的上下文库。旧 JSONL 导入文件保留。降级到不理解 SQLite 上下文的代码，必须先静默写者，经 context 的 `export_legacy` 导出并核对最后发布的 manifest，再显式放到旧配置路径；不能把旧 JSONL 当作仍包含迁移后的新增历史。自动更新不会替操作者执行有损格式降级。

## 清理和故障

维护任务/回滚引用的备份受保护；记录损坏或未知时禁止删除。清理预览有有效期、受保护集合和具体指纹，执行前重新盘点，不能将 token 当任意路径删除权限。取消中的备份/删除线程仍被观察，期间不释放部署互斥。归档失败删除自己创建的不完整文件，不影响旧备份。

## 验证

原归档边界、SQLite、备份删除与清理测试继续验证同一实现。`tests/operations/test_maintenance_contract.py` 从公开归档边界验证真实恢复；`test_versioned_maintenance.py` 验证保留校验引用并拒绝验证后的内容替换；子进程 rehearsal 验证停机快照、切换和失败回滚。验收使用临时部署和合成凭据，不恢复当前项目。
