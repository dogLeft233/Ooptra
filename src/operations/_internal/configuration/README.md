# 配置事务

`service.py` 拥有字段保存、内容版本、幂等请求和应用回执；`document.py` 拥有可信 Python 配置的 AST 保真补丁；`settings.py` 拥有显式加载、环境优先级及设置转换。公开入口见 [系统维护](../../README.md)。

## 权威状态与契约

`ConfigurationChange` 冻结边界已批准的嵌套输入；`ConfigurationRequest` 绑定请求 ID 和预期文件 SHA-256。`apply` 在部署变更文件锁及进程内配置锁中复核版本、读取、纯领域合并、补丁、校验、原子替换和同步所保存的运行字段；不回写无关环境覆盖。稀疏命令 `apply_latest` 在锁内针对最新值合并；旧 `save_fields` / 音量便利入口仍使用同一提交实现。

耐久请求记录不保存字段值，只保存载荷摘要、目标文件摘要、字段名和结果。先发布 pending，再替换配置，最后发布 saved；新实例查询 pending 时通过目标摘要确定 saved 或 unknown。重复请求不会重复写文件或套用旧版本；回执发布失败后的重试会恢复当前版本的运行字段。未知提交必须先读取当前配置后新建请求，不能猜测成功。

`configuration_transaction` 由应用入口持有至组件应用结束，与维护受理共用跨进程变更许可。作用域许可只在内部传给文件事务，结束即撤销，迟到子任务不能继续借用。请求取消只取消等待，已受理任务仍归模块观察。文件锁先于进程内配置锁；快捷语音音量保存遇到忙许可时拒绝，不能持输出锁阻塞等待一个正在等待输出锁的配置事务。

`record_application` 持久记录逐组件应用、失败和重启需求。部分失败不回滚已保存文件，不伪报全部成功；仅当前配置版本可重试热应用。同一 request_id 的 partial 重试保留已成功组件回执，应用层只重试失败组件及字段，不重新写文件、重新旋转口令或重启成功的桥接；旧版本请求拒绝热应用。应用内锁使同入口提交/应用按顺序完成，部署锁使其他进程的维护或配置变更不能插队。外部直接编辑配置不参与该协作锁，仍通过内容版本发现冲突。

## 输入与生命周期

HTTP schema、字段白名单和表单归一化归输入适配器；输出音量由 `OutputVolume` 解析。自动串门的纯领域合并规则由装配注入，配置模块不反向导入行为模块。可信配置校验会执行 Python 文档，不能用于不可信上传脚本。导入 settings 不读取密钥，显式加载才读配置/环境/本地文件；repr 隐藏 token、模型密钥及代理凭据。

请求查询记录当前部署的提交及应用事实；启动新进程不把历史 applied 当作新进程已经应用过配置。组件启动仍通过当前配置装配。配置正文与回执不是跨文件崩溃原子事务，unknown 状态明确保留此限制。

`platform.py` 提供平台只读配置端口，`credentials.py` 拥有 RSA 凭据解析与两文件保存。私钥确认后从 `RSAPrivateKey` 重新序列化，丢弃不属于密钥结构的尾随文本；字段补丁不执行用户配置。逻辑部署根的维护屏障、磁盘提交和运行字典同步共享许可，不因配置符号链接或异步取消绕过。

## 验证入口

`tests/operations/test_configuration.py` 与 `test_versioned_maintenance.py` 验证公开文件能力、CAS、幂等、回执恢复和应用状态；`test_voice_configuration_loading.py` 验证隔离环境加载及脱敏。原配置、稀疏串门、输出音量和 WebUI 取消测试继续经过同一实现。故障均使用临时文件、合成配置和可控运行端口。
