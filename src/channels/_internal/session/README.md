# 房间会话与传输绑定

属于 [渠道交互](../../README.md)。公开契约见 [api.py](../../api.py)，实现入口为 [service.py](service.py) 与 [binding.py](binding.py)。应用不需要比较 SDK/浏览器对象或维护房间锁。

## 状态与唯一拥有者

`RoomChannel` 持有 room revision、真实 SessionRef、房间转换锁、动作指纹/任务/终态，以及在途 I/O。`VoiceBinding` 持有实际账号、浏览器、采集任务、旧绑定清理和共享传输复用屏障。播放的帧/排空状态归 [输出执行器](../output/README.md)。

```text
Idle → Joining → Joined(SessionRef) → Retiring → Idle
                    ↓ 失败/未知         ↓
                 Uncertain ←────────────┘
```

Uncertain 保留最近已知目标和确认程度，拒绝新进房与输出；只能通过原会话退房/隔离恢复。进房、输出收尾和真实退房分别等待外部确认。超时不证明未产生副作用，旧会话不能因新 ID 而复用同一未隔离传输。

## 转换与绑定

- 进房携带预期 revision，自动请求不能覆盖已在房会话。手动切换先退役旧输出、确认退出，再加入目标；旧 join 迟到不能激活新绑定。
- 退房携原 SessionRef，过时请求在清理之前拒绝，不先停止新会话。取消房间网络操作会尝试补偿；无法确认清理时保留 Uncertain。
- `bind` 同步撤回旧绑定的应用可见性，实际清理由拥有的任务完成；`prepare_output` 等待释放和共享传输屏障后才复用/创建浏览器。
- 关闭先注销采集身份/回调，再等待 pump 和外部资源。清理失败不能通过丢弃引用隐藏，应用停止回执保留未关闭资源。
- `SendText` 与音频动作分别登记，原会话过期即拒绝；发送已开始后的取消/超时只确认未知效果，不自动换 ID 重发，也不额外退房。目标类型查询失败属于未执行，不能声称消息已经发出。
- `SetOutput` 的取消不额外退房，也不声称撤销已保存/应用的设置；失败阶段和未知效果通过动作台账查询。

房间事实只由本模块发布。上下文/生成启动失败时，应用发原会话 LeaveRoom 撤销；渠道不导入模型或记忆来猜测下一步。

## 外部等待与恢复

外部 I/O 有显式预算；即使外部协程忽略取消，也保留 pending 引用，拒绝复用。退役等待真实在途 push 结束后才停止原绑定，防止“先 stop，旧 push 随后又把音频排进去”。恢复仅清除音频自身导致的不确定性，不掩盖其他房间失败。

动作首个等待者撤销与重复等待者取消不同，台账保留原命令和唯一结果。精确保留期/容量见公开 `Channel` docstring。它是当前进程的幂等边界，重启后未知动作不自动重放。
